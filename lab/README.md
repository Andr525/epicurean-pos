# Epicurean Master: isolated POS screen lab

This review-only package runs the existing POS UI, client bridge and server interpretation adapter with a hash-verified snapshot of the actual BOH catalog. It uses synthetic staff/checks and scripted LLM/ASR responses. It does not demonstrate language understanding, noisy speech recognition or physical iPhone acceptance. Production files and BOH prices are unchanged.

## Start and reproduce in development

Use Node 22. From `lab`, run `npm ci --ignore-scripts --no-audit --no-fund`, then `npm test`. Chromium must be installed; set `CHROMIUM_PATH` if it is not `/usr/bin/chromium`. The browser uses the iPhone viewport descriptor, Chromium mouse clicks, actual visible controls, hit testing and screen screenshots. This is neither Safari nor trusted iPhone touch. The suite deliberately exits nonzero for product failures. `node server.mjs` starts a loopback-only UI at http://127.0.0.1:9443; phone hosting does not need npm dependencies.

Reports and per-case screenshots go into ignored `lab/artifacts`. Reports contain selectors, actions, rendered status/check text, structured draft/check state, catalog provenance and failures. `node report.mjs PATH_TO_RESULTS_JSON` writes a developer-readable reproducer beside the JSON. Submit only these controlled fixture reports and POS-only screenshots; inspect them before sharing. No automatic GitHub issue, message or upload is performed.

## Current cloud results

Eight scenarios: five pass, three fail. Manual BOH menu selection, multi-course correction/confirmation without duplicates, missing-price protection, guest-conversation gating and recorder restart pass. Logout/login reveals an obscured pricing selector; separate 2 and 2A identities are rejected; adding dessert later is rejected. The independent audit should reproduce the failures, not interpret a nonzero suite exit as infrastructure failure. Audio capture uses a fake browser microphone and scripted transcript. The physical microphone, interruptions, background noise and actual Deepgram/LLM understanding remain unverified.

## What can be automated on the phone

The owner opens this isolated site and taps **Run screen suite** once. The page can automate its own DOM controls, inspect visible order details, positions, prices/errors, corrections and login recovery, then return JSON evidence to the Mac. These are synthetic page events; they cannot establish native touch fidelity. Safari Web Inspector provides console/DOM/network diagnostics for this tab, not arbitrary phone control or an automatic pixel screenshot API.

The owner must approve access, unlock/pair the phone, choose the test tab, establish certificate trust, grant microphone permission with a real gesture, and handle lock/background/system prompts. Pixel evidence initially requires an owner screenshot of the POS tab. Do not automate or capture personal applications. Appium/XCUITest is a later candidate for native taps and screenshots; it requires separately approved installation, Xcode, signed WebDriverAgent, Developer Mode and device automation settings. None is installed or activated here. A free Apple account may permit manual signing; feasibility depends on the owner's Mac/iOS/Xcode versions. USB alone does not serve the Mac website to Safari; the proposed first connection uses same-Wi-Fi HTTPS for the site and USB for Inspector.

## Owner instructions — execute physical steps only after explicit approval

1. On your Mac, obtain the GitHub review branch `review/master-iphone-test-environment`. In its `lab` folder run `bash mac/preflight.sh`. This checks only Mac prerequisites; it installs nothing and does not enumerate/access your phone. If Node 22 is missing, report that result before installing anything.
2. After the scoped device approval, connect Mac and iPhone by USB, unlock the phone, and accept **Trust This Computer** if needed. Keep both on the same private Wi-Fi. In Mac System Settings → Network find the Mac's private IPv4 address. Do not use a public address or port forwarding.
3. Run `bash mac/make-cert.sh PRIVATE_MAC_IP`. Transfer only `certs/epicurean-test-ca.cer` to the phone using an owner-controlled method. Install the temporary certificate profile in Settings → General → VPN & Device Management, then enable its full trust under General → About → Certificate Trust Settings. Never transfer `.key` files. This temporary CA expands browser trust while installed: remove it after testing. No certificate bypass is used.
4. Copy `mac/owner-approval.example.json` to ignored `owner-approval.json`. Set `deviceAccessApproved` to true, `host` to the same private IP and `expiresAt` to a UTC time no more than one hour ahead. Keep spending limit 0, scope unchanged and native automation false. This record implements the approval already given; editing it does not grant permission by itself.
5. Start `node server.mjs --host=PRIVATE_MAC_IP --port=9443 --cert=certs/server.pem --key=certs/server.key --approval=owner-approval.json`. The server refuses unauthorized LAN serving and rejects requests after approval expires. Open the capability URL printed in your Mac terminal on the phone. Keep this URL private. A LAN firewall may ask for owner authorization; stop if the address/certificate does not match.
6. For diagnostics, enable iPhone Settings → Apps → Safari → Advanced → Web Inspector (path varies by iOS). Enable Safari's developer features in Mac Safari Settings → Advanced. In Mac Safari's Develop menu select your iPhone and **only the Epicurean local test tab**. No personal tab inspection. If this pairing fails, return the error rather than changing more device settings.
7. Tap **Run screen suite** once. The page performs the scenarios and returns a report to the Mac's `lab/artifacts`. **Stop** cancels the suite and recorder. PIN 5000 is synthetic staff, not a production account. Send/firing/payment/printing and external network APIs are blocked. The phone suite excludes microphone capture until separately armed through a real owner gesture; its scripted speech test does not evaluate ASR. Physical controlled utterances and interruptions are a subsequent acceptance step, not dozens of repeated manual dish tests.
8. Stop the server with Ctrl-C, close only the test tab, revoke this origin's microphone permission, remove the temporary CA profile/trust and local certificate keys, and restore newly enabled Inspector settings. No personal website data needs clearing.

## Safety and next milestones

No staging/production deployment, provider call, paid service, kitchen send/fire or price edit is authorized. Additional spend is $0. The server has a route allowlist, exact Host/Origin checks, local nonce, bounded request bodies, LAN capability cookie, expiry and CSP; Firebase SDKs are omitted in the test-served HTML and runtime integrations replaced with fixture adapters. This containment deliberately changes the test runtime: production Firebase authentication and live provider behavior are not tested.
